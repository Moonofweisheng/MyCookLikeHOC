## Why

吃完饭后由谁刷碗往往缺少共同认可、可追溯且足够轻松的决定方式，容易变成重复争论。鱼哥菜谱已经覆盖“找菜与做饭”，增加一个无需登录、可在单台设备上快速组建当次饭局并公平决定刷碗人的能力，可以自然补齐饭后收尾场景，同时用有参与感的揭晓动效提升重复使用意愿。

## What Changes

- 在首页增加“今天谁刷碗”的状态化入口，并提供独立的饭后分工页面，不新增底部 Tab。
- 引入统一的本地“饭搭子”成员库：每位成员拥有稳定 ID、昵称和内置食物角色贴纸，可改名、换角色、删除（可恢复）、彻底删除和恢复；彻底删除只移除成员档案，不抹除历史饭局快照。
- 引入“本次饭局”模型：用户从饭搭子中选择当次参与者、标记不在场或本轮休息；在组局阶段添加的人自动成为饭搭子并加入当前饭局，不再区分临时或常用身份。
- 统一用户心智：页面只展示“饭搭子”，添加即入库并加入当前饭局；不提供“临时加入”“保存为常用”或试玩后转换入口，用户通过删除不再需要的饭搭子完成清理。
- 提供简单透明的等概率规则：每顿饭只在本轮实际参与者中独立等概率抽取，不读取或调整任何成员的历史完成次数。
- 提供“餐盘漩涡洗牌＋泡沫封印＋自动清场揭晓”动效：成员围绕餐盘加速换位、聚拢急停，随后由 Lottie 自动播放泡沫卷走、水花和结果爆发，用户无需拖动海绵。抽签结果在动效开始前确定并持久化，用户可跳过一次性揭晓动效。
- 支持完成打卡、有限原因的重新抽取、当前饭局恢复及历史记录；同一自然日完成一局后可显式“再开一局”，每顿饭独立保存且不会覆盖当天早先记录，最近饭局无论是否打卡均可在确认后删除。
- 建立模块化插画资源方案：生产一组本地食物角色、餐盘和自动揭晓 Lottie 动画资源，角色、昵称和结果卡由 Vue 动态渲染；不引入 Rive、视频或序列帧依赖。
- H5 与微信小程序保持相同的成员、规则、结果和恢复行为；默认播放完整动效，允许震动、粒子数量和系统减少动态效果偏好在表现层降级，不额外开放应用内动效开关。
- 第一版数据保存在当前设备，不引入登录、家庭邀请、多人实时同步、服务端防篡改或真人头像上传。

## Capabilities

### New Capabilities

- `dish-duty-draw`: 覆盖饭搭子管理、本次饭局组建、公平抽签、动效揭晓、异常恢复、完成打卡和历史记录的用户可观察行为。

### Modified Capabilities

- 无。

## Impact

- 页面与导航：影响首页入口，新增饭后分工页面及其页面配置与路由生成结果。
- 状态与数据：新增本地持久化的饭搭子、饭局、抽签结果和历史记录模型；同一日期允许保存多条饭局记录，以饭局 ID 而非日期作为唯一身份；不涉及 Supabase 表、RPC、Storage 或数据库迁移。
- UI 与资源：新增可复用的饭搭子角色、抽签舞台和泡沫揭晓组件，以及位于 `src/static` 的模块化 SVG 与 Lottie 资源；动效升级复用既有角色和餐盘资源，重点调整运动编排、泡沫层级、自动清场和结果爆发，不依赖新增位图素材。
- 依赖与兼容性：新增受控的 Lottie 播放适配层，H5 与微信小程序分别使用可兼容的播放器实现；业务层不直接耦合平台播放器，并保留 CSS/静态阶段降级路径。
- 安全与隐私：第一版不读取微信头像、不请求相册、不上传成员数据，不新增凭据或网络接口；本地记录可被设备操作者修改或清除，因此产品不承诺强制或不可篡改的绝对公平。
- 验证：需要更新 UI smoke 检查，并执行类型检查、lint、H5 构建、微信小程序构建及移动端人工动效验收。
