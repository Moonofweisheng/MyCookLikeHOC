## Context

变更动机见 `proposal.md`，行为要求见 `specs/dish-duty-draw/spec.md`。当前 `src/pages/dish-duty/index.vue` 已注册 `onShareAppMessage`，会根据 `currentWinner` 生成好友分享标题，但未注册 `onShareTimeline`。项目其他主要页面已经直接使用 uni-app 页面生命周期钩子接入朋友圈分享。

饭后分工的抽签结果会在揭晓动画开始前写入 store，因此 `currentWinner` 在 `shuffling`、`sealed` 或 `revealing` 阶段可能已经存在，但用户尚未看到结果。朋友圈分享必须以用户可见阶段为准，不能仅以 store 中是否存在获选人作为判断条件。

## Goals / Non-Goals

**Goals:**

- 复用项目现有的 uni-app 页面分享模式，在微信小程序系统菜单中启用朋友圈分享。
- 仅在结果已揭晓或已完成时公开获选人昵称，避免通过分享标题提前暴露已持久化但尚未揭晓的结果。
- 保持分享目标无状态，让接收方按自己设备的本地数据进入饭后分工页。

**Non-Goals:**

- 不抽取通用分享 composable；单页增加一个生命周期钩子不足以证明新抽象的必要性。
- 不改变现有好友分享钩子的标题、路径或触发方式。
- 不生成分享海报或自定义图片，不增加页面内按钮、网络请求和分享结果回调。

## Decisions

### 1. 在饭后分工页直接注册朋友圈分享生命周期

在 `src/pages/dish-duty/index.vue` 中增加 `onShareTimeline`，与首页、分类、搜索和菜谱详情页保持同一接入层级。回调在用户触发系统分享时读取最新响应式状态，以支持从组局、动画、揭晓到完成阶段之间的标题变化。

备选方案是在页面中增加一个分享按钮并主动调用平台 API。该方案会改变 H5 布局、重复系统菜单能力，并需要额外处理平台判断和失败反馈，因此不采用。

### 2. 朋友圈标题由可见结果状态与获选人共同决定

朋友圈分享回调仅在 `showResult` 为真且 `currentWinner` 存在时返回“今天轮到{昵称}刷碗”，其他状态返回“今天谁刷碗？来公平抽一个”。`showResult` 已由页面统一定义为 `revealed` 或 `completed`，可避免抽签结果在揭晓动效期间通过分享标题提前泄露。

备选方案是只复用现有好友分享对 `currentWinner` 的判断。由于结果会先持久化再播放动画，该判断无法满足“结果尚未揭晓时使用通用标题”的规格，因此不采用。本变更不顺带修改好友分享，以保持范围与兼容性。

### 3. 朋友圈分享载荷不附带业务 query

朋友圈分享使用平台当前页面作为目标，仅返回标题，不传递成员 ID、饭局 ID、获选人昵称或历史数据 query。接收方打开后仍由现有页面初始化逻辑读取接收方设备上的本地 store；不存在跨设备恢复链路，也不需要新增路由解析。

备选方案是把饭局或结果编码进 query，让接收方看到分享者的结果。该方案会扩大产品能力与隐私面，并与当前“数据仅保存在本设备”的规格冲突，因此不采用。

### 4. 使用契约检查、双端构建和微信端人工验收

更新 `scripts/smoke-ui.ts`，检查饭后分工页注册了 `onShareTimeline`、标题分支依赖可见结果状态，并且未向朋友圈分享载荷加入业务 query。执行 `pnpm type-check`、`pnpm lint`、`pnpm smoke:ui`、`pnpm build:h5` 和 `pnpm build:mp-weixin`。

自动化检查无法真实打开微信系统分享菜单，因此还需在微信开发者工具或真机人工覆盖：未开始抽签、揭晓动画中、已揭晓、已完成四种状态，确认朋友圈入口存在、标题正确、分享可打开饭后分工页；同时确认接收端只显示其本机数据。

本次人工验收已在微信开发者工具覆盖上述四种状态，并打开平台提供的“小程序分享页”独立环境。该环境以空本地状态进入饭后分工页，未恢复发送端创建的成员、结果或历史，因此将其作为接收端数据隔离的验收证据。未实际发布朋友圈内容或从另一台真机打开分享，真实客户端的发布与跨设备打开链路仍作为残余风险保留。

## Risks / Trade-offs

- [微信朋友圈分享能力受基础库版本、主体权限和客户端环境限制] → 使用官方页面生命周期接入，并以开发者工具或真机验收实际菜单；应用内不伪造成功状态。
- [获选人昵称会作为朋友圈标题公开] → 仅在用户主动选择分享到朋友圈且结果已揭晓后使用昵称，分享载荷不包含其他成员和本地标识。
- [源码契约检查不能验证微信客户端真实分享行为] → 同时执行微信小程序构建，并将四阶段人工分享验收列为完成任务。
- [未执行真实朋友圈发布与另一台真机打开] → 已通过开发者工具系统“小程序分享页”的独立空本地环境验证接收端数据隔离；上线后仍需关注微信客户端、基础库和主体权限对真实发布链路的影响。
- [现有好友分享仍可能在动画期间读取已持久化获选人] → 本次只补齐朋友圈行为并为其按规格隔离；好友分享语义如需统一，应另起行为变更，避免无意扩大范围。

## Migration Plan

1. 随页面代码发布朋友圈分享钩子和契约检查，不需要数据迁移、配置开关或分阶段后端部署。
2. 发布前完成 H5 与微信小程序构建，并在微信开发者工具或真机验证系统分享菜单与四种结果阶段。
3. 若需要回滚，移除新增朋友圈分享钩子和对应契约检查；既有好友分享、本地成员与饭局记录保持不变。
