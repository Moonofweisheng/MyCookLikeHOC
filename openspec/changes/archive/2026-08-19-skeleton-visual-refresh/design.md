## Context

现有骨架屏由 `src/components/SkeletonBlock.vue` 统一提供，复用于推荐卡、分类入口、搜索结果和详情页；页面整体已经使用 `--cook-*` 视觉 token 与粗描边插画卡片。详见 `proposal.md` 的 Why 和 `specs/skeleton-loading-visuals/spec.md`。

## Goals / Non-Goals

**Goals:**

- 通过现有 `--cook-*` token 增加骨架专用的暖中性色和低对比度高光。
- 让通用骨架块能表达文字、图片、头像/图标三类占位语义。
- 保持最终内容结构、卡片尺寸、加载时序和现有页面状态逻辑不变。
- 让 H5 与微信小程序使用简单、兼容的 scoped CSS 完成一致渲染。

**Non-Goals:**

- 不改 API、数据模型、Supabase、路由或请求重试逻辑。
- 不重做真实菜谱图片占位 `RecipeImage` 的错误态视觉。
- 不引入第三方骨架屏或动画依赖。
- 不在本次变更中新增暗色主题或页面级动效系统。

## Decisions

1. **沿用 `SkeletonBlock`，增加语义 props。**
   继续以现有组件作为唯一基础，增加 `variant`（文字、图片、头像/图标）和必要的 class hook；默认保持文字语义，减少现有调用的破坏性。相比拆分多个组件，这能避免四类页面产生新的视觉分叉。

2. **采用 token 驱动的暖中性色。**
   在 `src/App.vue` 的 `page` token 中定义骨架底色、图片底色和高光色，默认底色使用接近 `--cook-image-bg` 的浅米色，高光使用接近 `--cook-paper` 的低透明度颜色。相比组件内散落 hex 值，token 更容易在 H5/小程序和后续主题调整中保持一致。

3. **按语义控制描边，而非全部保留。**
   文字变体去掉独立深色描边；图片变体允许保留必要的容器边界；头像/图标变体使用形状本身表达边界。这样保留插画风格的结构感，同时避免外层卡片重复描边。

4. **使用单层 shimmer，不再叠加纹理。**
   保留简单的线性渐变背景位移动画，降低透明度并将周期调整到约 1.8 至 2.1 秒；删除伪元素网格层。相比静态灰块，shimmer 仍能反馈加载状态；相比当前多色和纹理叠加，跨端渲染更稳定。

5. **页面骨架只调整组件参数和必要的容器 class。**
   `RecipeCardSkeleton`、`CategoryShortcutSkeleton` 与 `RecipeDetailSkeleton` 继续复用现有布局，图片区域标记为图片语义，头像/分类图标标记为头像/图标语义，标题与描述使用文字语义。不会复制新的页面骨架结构。

## Risks / Trade-offs

- [风险] 低对比度颜色在部分低亮度屏幕上可能不够明显 → 以真实页面背景为基准做 H5 390x844 人工验收，并保留可见但不刺眼的高光差值。
- [风险] uni-app 小程序对复杂背景动画支持存在差异 → 仅使用现有线性渐变、背景位移和简单伪元素/类选择器，运行 H5 与 mp-weixin 构建验证。
- [风险] 调整默认样式可能影响未显式指定变体的调用 → 将默认值定义为文字变体，并执行现有 UI smoke 检查和类型检查。
- [取舍] 不为每一种卡片建立独立颜色方案 → 牺牲少量页面个性，换取跨页面一致性和后续维护成本降低。

## Migration Plan

无需数据迁移或发布前脚本。实现后先执行 `pnpm smoke:ui`、`pnpm type-check`、`pnpm lint` 和 `pnpm build:h5`，再执行微信小程序构建；若视觉验收不通过，可仅回滚骨架 token 与组件样式，页面业务代码和接口无需回滚。
